## 2026-06-13 - Optimization: deserialize vs from_value
**Learning:** Performance memory pattern states that when deserializing from intermediate `serde_json::Value` or `serde_yaml::Value`, prefer `T::deserialize(&value)` over `from_value(value.clone())` to avoid expensive deep clones. However, when consuming the entire `Value` tree at the end of parsing, prefer `from_value(value)` (without cloning) so Serde can move strings and data directly without re-allocating.
**Action:** Identified redundant `clone()` calls in `xdk-openapi/src/parser.rs` when pre-loading OpenAPI components into the context from intermediate `serde_json::Value` / `serde_yaml::Value` trees. Patched code to use `T::deserialize(&value)` instead of `serde_json::from_value(value.clone())` and `serde_yaml::from_value(value.clone())` to avoid unnecessary deep clones of JSON/YAML subtrees.
